# DAY 2026-09-12 — PIX payment provider (stub)

## Goal
Pragmatic PIX provider interface without live keys, wired into the existing invoice payment-link flow, plus a JWT billing endpoint.

## Deliverables

| Path | Role |
|------|------|
| `backend/services/pix_payment_service.py` | `create_pix_charge(amount_cents, description, client_ref)` |
| `backend/tests/test_pix_payment_service.py` | Stub / Asaas not_configured / keyed stub |
| `backend/routes/finance_routes.py` | Payment-link uses PIX stub when Stripe unavailable; `billing_router` |
| `POST /billing/pix-charge` | JWT endpoint wrapping the stub |
| `backend/config.py` + `.env.example` | `PIX_PROVIDER`, `ASAAS_API_KEY` |

## Env
- `PIX_PROVIDER=stub` (default) → `{provider, qr_payload_stub, txid, status: pending}`
- `PIX_PROVIDER=asaas` without `ASAAS_API_KEY` → `status: not_configured`
- `PIX_PROVIDER=asaas` with key → pending stub payload (no live HTTP in this layer)

## Wiring
`POST /finance/invoices/{id}/payment-link` still prefers Stripe when configured; otherwise calls `create_pix_charge`, keeps local signed `payment_url`, stores `txid` in `payment_reference`, and returns a `pix` object.

## Tests

python -m pytest tests/test_pix_payment_service.py -q

## Not in scope
Live Asaas/Open Finance calls, QR image rendering, webhook reconciliation.
