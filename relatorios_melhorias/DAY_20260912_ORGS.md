# DAY_20260912 — Organization multi-tenant MVP

Data: 12 de setembro de 2026

## Objetivo

Fechar o gap do próximo sprint com um **MVP pragmático de Organization** multi-tenant:
criar org, listar, detalhe (só membro) e adicionar membro existente por e-mail.

## Entrega

### Backend

| Item | Detalhe |
| --- | --- |
| Models | `Organization`, `OrganizationMember` em `backend/database.py` |
| User | `organization_id` nullable (FK opcional; migração SQLite local se coluna ausente) |
| Routes | `backend/routes/org_routes.py` registrado em `main.py` |
| Auth | JWT via `get_current_user`; IDOR → **404** se não-membro |

Endpoints:

- `POST /orgs` — cria org; caller vira `owner` (+ membership)
- `GET /orgs` — lista orgs do usuário (com `my_role`)
- `GET /orgs/{id}` — detalhe + membros se member
- `POST /orgs/{id}/members` — add por e-mail (`member`\|`admin`); user deve existir; só owner/admin

### Frontend

| Item | Detalhe |
| --- | --- |
| Página | `frontend/app/dashboard/orgs/page.tsx` (trust-shell) |
| Nav | link **Orgs** na row **Operações** do `dashboard/page.tsx` |

## Decisões

1. Slug auto a partir do nome se omitido; unique com sufixo `-2`, `-3`…
2. Add member exige User existente (sem stub) — diferentemente do invite de equipe.
3. Role na criação de membro: só `member`\|`admin` (owner só no create).
4. `User.organization_id` preenchido só se ainda null (não sobrescreve).
